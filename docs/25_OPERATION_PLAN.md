# MARIA Python 위험 분석 서비스 운영 기준

## 2026-11-05 현재 구현 상태

이 문서는 2026-10-29 운영안과 검토 이력을 보존한다. 현재 위험등급은 상품 유형별로 적용한다. 주식은 KIS 현재 투자주의·경고·관리 상태, ETF·펀드는 설정 기간과 VaR/투자자산 기준을 사용한다. 등급·현재 주식 분류·MARIA 소비자 연결 및 로컬 통합 검증은 완료했다. 자세한 계약은 [구현 문서](../IMPLEMENTATION.md), [Python↔MARIA 계약](../MARIA_SYNC_CONTRACT.md), [운영 준비](../OPERATIONS_READINESS.md)를 따른다.

Python 239개 테스트와 MARIA 위험등급 관련 총 201개 테스트를 통과했다. 운영 배치와 MARIA 자동 Pull은 비활성 상태다. NCP 인프라 검증과 2026-11-19 특별 거래시간 확인은 별도 남아 있다. 아래의 당시 “미구현” 표기는 문서 작성 당시 기준이다.

사용자가 제시한 운영안(2026-10-29)을 기준으로 한다.

1. KRX 공식 거래일·거래시간을 확인한다.
2. 정상 거래일에는 15:40, 변경일에는 정규장 종료 10분 후 배치를 시작한다.
3. KIS에서 기준일 종가를 조회하고 유효성 및 데이터 완전성을 검증한다.
4. 검증에 실패하면 기존 위험등급을 유지하고, 실패한 데이터만 재시도한다.
5. 검증을 통과한 데이터로 변동성·위험등급을 계산한다.
6. 계산 결과 검증 후 새로운 위험등급을 확정한다.
7. 확정된 결과만 MARIA에 동기화하며, 동기화 실패 시 별도로 재시도한다.

## 적용 시 구분

- [결정] 15:40 또는 종료+10분은 배치 시작 정책이다. KIS의 공식 종가 반영 보장을 확인한 것으로 해석하지 않는다.
- [결정] 실패 종목의 이전 정상 결과는 보존하되 기존 합의인 priceTo 기준 3거래일 초과 만료 정책을 유지한다. 실패나 재동기화로 asOf·priceTo를 새 값처럼 바꾸지 않는다.
- [확인] 유효한 날짜·양수 가격·완전한 표본만으로 종가의 최종 확정을 증명할 수는 없다. 시장 구분과 API 필드 의미도 일관돼야 한다.
- [제안] 실패 데이터의 재시도는 종목 단위로 하며 해당 종목의 전체 3년 수정주가를 다시 조회한다. 성공 종목은 재조회하지 않는다. 과거 조정이 바뀔 수 있으므로 일부 날짜를 새 시계열에 이어 붙이지 않는다.
- [확인] 재시도 횟수·간격·중단 시점, 영구 품질 미달과 일시 수집 장애의 구분은 아직 구체화가 필요하다.
- [결정] Python은 검증·계산을 마친 종목의 가격과 등급을 함께 확정 저장하며, API에는 확정 저장된 결과만 제공한다. 실패 시 종목별로 롤백한다.
- [확인] 기존 시스템 경계에 따르면 MARIA가 GET /grades를 호출해 사본을 저장한다. Python이 MARIA DB에 접근하거나 동기화를 직접 수행하는 범위로 확대하지 않는다. 동기화 실패 재시도는 MARIA 측 작업이며 수집 재시도와 별개다.

## 실제 구현 상태

기본 수집·계산·API·종목별 원자적 저장·실패 보존·만료 코드는 구현돼 있다. OS 배치 작업 등록, 종목별 후속 재시도 관리, MARIA 동기화 구현은 완료되지 않았다.

사용자가 제공한 KRX 2023~2026년 XLS의 휴장일을 기존 1,099일과 대조했으며 차이는 0일이다. 공식 거래시간 변경일까지 반영된 운영용 달력은 아직 연결하지 않았다. 자세한 상태는 24_KRX_OFFICIAL_CALENDAR_REVIEW.md를 따른다. 위 운영 기준을 문서화한 것이 미완료 기능까지 구현됐다는 뜻은 아니다.

## 운영안 검토 시 보완할 사항

- [제안] 일시 장애(타임아웃·호출 제한·기준일 자료 누락)는 실패 종목만 재시도하고, 영구 품질 미달(이력 부족·장기 거래정지·종목 코드 불일치)은 원인 해결 전 자동 재시도를 멈춘다. 재시도 횟수·간격·마감 시각은 별도 합의한다.
- [제안] 6번의 확정은 '서비스의 데이터·계산 검증을 마치고 원자적으로 저장한 결과'로 정의한다. 공급자의 추후 정정 가능성이 없어졌다는 뜻으로 사용하지 않는다.
- [제안] MARIA 동기화는 같은 확정 결과를 다시 받아도 중복되지 않게 저장하고, 늦게 도착한 과거 결과가 최신 결과를 덮어쓰지 않도록 버전을 비교한다. 동기화 재시도 때문에 이미 성공한 시세 수집·계산을 재실행하지 않는다.
